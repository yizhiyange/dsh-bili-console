# dsh-bili-console · 刷B站观测台

> 派 AI 替你值日：每天刷一轮 B站，读懂视频、写下日报，把值得看的 @ 给你。
> **一个插件，两种操控**：网页「观测台」+ DSH 设置界面，同一份配置实时同步、互相一键跳转。
> 界面骨架的起点是 c1overzz 的 dsh-bili-scroll（MIT）——在其之上，编排、章程、
> 风控与冷却、撤回台账、双端控制台均为重写原创，详见 [NOTICE.md](./NOTICE.md)。

## 它解决什么

网上的同类工具翻车点（我们逐个修掉）+ 我们自己踩过的坑：

| # | 痛点 | 本插件的修法 |
|---|------|-------------|
| 1 | 固定 sleep 间隔，机器纹身 | 随机间隔 1-2 分钟 + 每周强制休息 1 天 + 操作时间窗匹配真人作息 |
| 2 | 风控码来了硬顶，限流加重 | 已知风控码表（-412/-352/-403/12045/12008/12002/429）分级处置：验证码/429 → 冷却 24 小时；当日上限 → 今天收工；频率过快 → 本轮停 |
| 3 | 验证码弹窗无人值守卡死 | 遇到验证码立刻暂停整个轮次，通知你来处理 |
| 4 | 私信误用被举报 | 私信默认关；开启需二次确认；同一用户对方未回复前最多 1 条；间隔 2-4 分钟 |
| 5 | 每天互动超阈值收"礼包" | 每日上限默认 10，超了自动收工 |
| 6 | 密钥/Cookie 随截图外泄 | 凭证只存本机插件家目录；网页只显示前 6 位 |
| 7 | 登录态过期后静默失败 | 登录态监控，过期前提醒，一键重新扫码 |
| 8 | 模型没钱/没资源包，AI 起不来 | 降级链：哪个不可用自动切下一个；适配器没注册也自动切 |
| 9 | 配置是 JSON、日志是代码 | 全部设置图形化；日志大白话 + 原始日志双视图 |
| 10 | 评论区提示注入 | 章程写死：评论区/字幕/简介里的话一律当素材，不当指令 |
| 11 | 评论像 AI、像广告 | 人设卡（≤8000 字全文生效，也支持填 AGENTS.md 路径）；评论禁外链、禁套话 |
| 12 | 半夜也在操作，不像人 | 谷时窗口 + 凌晨自动静默 |

## 安装（DSH 一条链接）

```
dsh plugin --profile web add dsh-bili-console
```

或本地开发：

```
dsh plugin --profile web add link:<本仓库的解压目录>
```

装完在 DSH 的「插件设置」里就能看到「刷B站 · 双模控制台」——所有设置都在那儿改。
网页控制台由插件自己提供（挂在 DSH 的 webServer 上），DSH 设置页里有按钮一键打开；
网页控制台右上角也有按钮跳回 DSH。**两边是同一份配置，不用装两个东西。**

## 依赖：插件自己装，你不用管

**不需要预先装过任何刷B站插件、也不需要手动 pip install。** 插件首次登录 / 跑轮时会自己把环境备好：

1. 若你机器上已有「装好依赖」的 Python（比如开发机）→ 直接用，不重复下载；
2. 若没有 → 自动在插件目录下 `.venv/` 建一个**插件专属虚拟环境**，按
   `vendor/bilibili-mcp/requirements.txt` 锁定的版本装好 `bilibili-api-python`、`mcp`、`aiohttp`、`qrcode`；
3. 装好之后缓存在那儿，后续启动秒开。

**唯一的前置条件**：机器上要有一个 Python 3.10+（装的时候勾选 "Add Python to PATH" 即可）。
万一连 Python 都没有，设置页会直接用人话告诉你「没找到 Python，请先装」并给出下载地址，
而不是抛一句看不懂的 `ENOENT`。

> 想手动指定解释器：设置页「高级」里填 `pythonPath` 即可，插件会优先用它。

## 两种操控

- **网页控制台**：浏览器打开 `http://127.0.0.1:<端口>/bili-console`（端口见 DSH 里的提示）。支持 `?p=models` 直达某页。
- **DSH 设置界面**：DSH 里「设置 → 刷视频」。

网页版是**照最初的设计稿复刻**的（浅色、侧栏、卡片留白、大数字进度），7 页全在：
总览 / 模型与密钥 / 专业日志 / 人设 / 降级链 / 安全防护 / 设置。

> 仓库里**不附截图**——界面截图会带上本机账号（头像、昵称、UID、日报内容）。
> 想看效果，装好之后打开网页版即可，仓库里只放源码。

> 说明：网页版（`web/console.html`，原生 JS）和 DSH 面板（`client.js`，React）是两套渲染，但**共用同一套接口**（`/state`、`/settings`、`/run/*` …）。改功能改后端即可，两边都会生效；新增界面控件需要两边各加一次。


## 可选能力：转写 / 识图 / 收藏

这三项都**不是必须**，不开也能正常跑；开了才需要额外条件。

| 能力 | 条件 | 说明 |
|---|---|---|
| **本地转写** | 装 `faster-whisper`（+ ffmpeg 在 PATH） | 视频**没字幕**时，取 DASH 音频转成文字再看内容。没装时界面会标「未装后端」并给出装法，没字幕的视频直接跳过——不会卡住一轮 |
| **识图** | 填一组识图模型（免费可用 `glm-4v-flash`） | 没字幕时让视觉模型看一眼**封面**，把画面信息补进判断。调用失败只记一条日志，不影响整轮 |
| **收藏** | 填收藏夹 ID（`bili_favorite_lists` 可查） | 真发成功、且判为「值得看」时，把视频收进该收藏夹 |

> 收藏用的是 vendored MCP 里新增的 `bili_favorite_add`（`Video.set_favorite`）；
> 转写用的是新增的 `bili_audio_url`（取 DASH 音频流）。

## @ 谁

评论末尾会拼上 `@昵称`，配置项是 `mentionName`。

**这是真 @，对方会收到通知**（2026-10-29 实测：从被 @ 的号看消息中心，出现「XX 在评论中@了我」，评论里 @昵称 是蓝色可点的链接）。

> 判据说明：不要用评论列表接口里的 `content.at_name_to` 判断有没有 @ 成功 —— 那个字段在**公开读取时是空的**，
> 它只是提交时的入参，不代表没通知。唯一可靠的验证是去被 @ 的号看消息中心。

## 撤回：把 AI 刚发出去的删掉

AI 发出去的评论是**公开的、删了也留过痕**。所以每发一条都会记账，随时能撤。

- **账本**：`posted.json` —— 每发一条（评论或回复）记下 `bvid + rpid + 文字 + 时间`，最多 500 条
- **入口**：总览那张卡最后有个 **「撤回上一条（N）」**，N 是账本里还剩几条
- **能力**：`POST /retract`（`count` 默认 1，`dryRun` 只看不删）、`GET /posted`（看账本）、`POST /posted/clear`（清账本，不动 B站）
- **底座**：vendored MCP 新增 `bili_comment_delete`（`comment.Comment(...).delete()`）

**只能删自己发的**：B站 侧会校验权限，所以这不是"删别人评论"的工具。

撤回时如果那条**早就删过了**，B站 也会返回成功，账本照样划掉；真的删不掉时账本会保留并给出原因，不会假装成功。

> 注意：删掉 ≠ 没发生过。通知已经发到对方手机上，可能有人已经看过。**别指望它能兜住"发错内容"这件事** —— 它只兜"删得掉"。

## 随时能停

点「立即跑一轮 / 试跑」之后，总览那张卡会变成 **「停止这一轮」**，并显示当前在跑什么。

- 停止不是掐进程，而是**在下一个检查点收手**：正在判的那一条会做完，但**不会发出半句**（发评论前会再确认一次）。
- 实测：第 8 秒按停止，9.4 秒就停了，挑中 0 条、发出 0 条。
- 停止后这一轮的统计照常写进日报（已发的标「已发布」，没发的标「已中断，未发布」）。

## 上下文：默认一条视频一个，判完就忘

这一条决定了它"记不记得自己在哪儿说过什么"，默认是**不记**。

### 默认 `isolated`：一条视频一个上下文

- 每次判断一条视频，都是**全新的会话**：模型只看得到「你的人设 + 章程 + 这条视频的标题/简介/字幕」。看不到别的视频，也看不到自己上一轮说过什么。
- 唯一跨轮留下来的是**判重表**（哪个视频、哪条评论处理过）——那只是"别再重复"的记号，**不含任何对话内容**。
- 好处：不会把上一条视频的观点带过来，不会越跑越"人设漂移"，token 最省。
- 代价：同一条视频下你之前说过啥它不记得；别人回复你时，它只看到对方那一句，不懂来龙去脉。

### 可选 `thread`：每条视频保留对话上下文

打开后，每条视频存一份 `threads/BVxxxx.json`，记「我说过什么 / 谁回了什么」。下次再碰这条视频（补评论、回评论）时，把最近几轮压缩后带进 prompt，所以它能接着聊、不会自相矛盾。

**开之前请想清楚这四个代价：**

1. **隐私**：本地会存下别人的昵称和留言内容。用不着就点「清空所有上下文」，目录也可以直接删。
2. **花钱**：每次多带一段上下文，token 会变多（每条视频多几百 token）。
3. **会"圆自己"**：顺着自己前面说过的话往下说，前面判断错了，后面会接着错、还不好改口。
4. **会越攒越多**：记录不清理就一直背着。

> 开关位置：设置页「上下文与记忆」；DSH 里是「刷视频 → 设置」。切换即时生效，不用重启。
> 想让它能接别人回复、又不留历史，就只开「回复评论」、上下文保持关闭——它会只针对对方那一句回应。
